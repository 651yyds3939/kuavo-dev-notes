## 1. 描述

- 本文介绍如何使用键盘控制机器人手臂末端位置的功能
- 示例代码位于 `<kuavo-ros-control>/src/manipulation_nodes/motion_capture_ik/scripts/test/keyboard_control_robot_arm_demo.py`
- 支持通过键盘按键实时控制机器人手臂末端执行器的位置和手部开合

以下用**「公司部门协作」**比喻 Kuavo 手臂键盘控制涉及的 ROS 通信流程：ROS Master 类似公司总机，各终端节点类似不同部门。

想要让机器人的手臂动起来，公司内部需要经历以下四个标准步骤：

### 第一步：夺取控制权（打内线电话 —— ROS Service）

**环节：** Python 脚本 $\rightarrow$ 机器人模式切换服务

机器人上电后，通常处于“默认待机”或“自平衡”状态（类似自动驾驶）。Python 脚本需先通过 Service 获取控制权限。
* **动作：** Python 脚本调用 `/change_arm_ctrl_mode` 这个**服务 (Service)**，并发送了参数 `2`[cite: 3]。
* **大白话：** 脚本通过 Service 请求切换模式：“将手臂控制权切换到外部控制模式。”[cite: 3, 4]。管家说：返回成功（返回 `result: True`）[cite: 4]。
* **核心特点：** 服务（Service）就像打电话，是**双向同步**的。请求须等待成功/失败响应，流程才能继续。

### 第二步：确认当前位置（看 GPS 导航 —— TF 坐标树）

**环节：** Python 脚本 $\rightarrow$ 空间定位系统 (TF Buffer)

在命令手臂往前走 0.05 米之前，须先读取当前末端位姿。
* **动作：** 脚本通过 `tf2_ros` 库查询 `base_link`（机器人的身体基准）和 `zarm_r7_end_effector`（右手末端）之间的相对位置[cite: 4]。
* **大白话：** 读取 TF 当前位姿：“哦，原来现在右手在坐标 X: -0.05, Y: -0.25 的位置啊。”[cite: 4]。作为后续位移指令的参考。

### 第三步：下达目标指令（发全员广播 —— ROS Topic 发布）

**环节：** Python 脚本 $\rightarrow$ C++ 逆解IK 节点

按键触发位移指令，意思是“往前走”。脚本只发布目标位姿。
* **动作：** 脚本将刚才查到的当前 X 坐标加上 0.05（步长），打包成一个 `twoArmHandPoseCmd` 格式的消息，然后发布到 `/ik/two_arm_hand_pose_cmd` 这个**话题 (Topic)** 上[cite: 3, 4]。
* **大白话：** 脚本发布 Topic，在公司走廊里喊了一声（发布话题）：“要求右手移动到目标坐标 X: 0.00, Y: -0.25，姿态保持不变！”[cite: 4]。
* **核心特点：** 话题（Topic）类似广播，**单向异步**；发布后不阻塞（继续监听键盘），不等待订阅方回执。

### 第四步：翻译与干活（接听广播并执行 —— C++ 节点与 MuJoCo）

**部门：** C++ 逆解IK 节点 $\rightarrow$ MuJoCo 仿真车间（或真实电机）

* **动作 1（翻译）：** 已启动的 C++ 节点 `arms_ik_node` 一直在监听Topic。它听到了目标坐标，立刻掏出复杂的数学公式（运动学逆解 IK），疯狂计算：“为了让手到达 X: 0.00，肩膀的电机需要转 15度，手肘需要转 30度，手腕转 5度……”
* **动作 2（干活）：** C++ 节点算出了这 7 个关节的精确角度后，再次通过另一个话题（通常是底层的 Joint Command），把这些角度发给 MuJoCo 仿真器。
* **大白话：** IK 节点将目标位姿，翻译成了转换为关节角，仿真车间的虚拟电机一通猛转，仿真界面可见机器人的手往前动了一下！

---

**总结一下：**
**流程概述**：Python 脚本，通过 Service 获取权限，经 Topic 发布目标位姿；C++ 节点完成 IK 并驱动仿真。**

这就是 ROS 通信在实际项目中最经典的运作方式！

## 2. 编译与启动

### 2.1 编译

```bash
cd <kuavo-ros-control>
catkin build motion_capture_ik
```

### 2.2 启动参数

键盘控制节点的可选参数：

- `--hand`: 选择控制的手臂，可选 `left` 或 `right`，默认为 `right`
- `--step`: 移动步长，单位为米，默认值为 0.05

逆解节点的可选参数：

- `control_hand_side`: 控制的手臂选择
 - `0`: 左臂
 - `1`: 右臂
 - `2`: 双臂

### 2.3 启动示例

1. 启动机器人仿真环境：
```bash
cd <kuavo-ros-control>
source devel/setup.bash
roslaunch humanoid_controllers load_kuavo_mujoco_sim.launch
```

2. 启动手臂逆解节点：
```bash
cd <kuavo-ros-control>
source devel/setup.bash
roslaunch motion_capture_ik ik_node.launch control_hand_side:=1
```

3. 启动键盘控制节点：
```bash
cd <kuavo-ros-control>
source devel/setup.bash
rosrun motion_capture_ik keyboard_control_robot_arm_demo.py --hand right --step 0.03
```

## 3. ROS接口

### 3.1 话题

**发布的话题：**

- `/ik/two_arm_hand_pose_cmd`
 - 类型：`motion_capture_ik/twoArmHandPoseCmd`
 - 描述：发布手臂末端 POSE 给 IK

- `/control_robot_hand_position`
 - 类型：`motion_capture_ik/robotHandPosition`
 - 描述：控制手部开合（仅支持实物）

**订阅的话题：**

- `/ik/result`
 - 类型：`motion_capture_ik/twoArmHandPose`
 - 描述：订阅IK求解结果，获取当前手臂位置

### 3.2 服务

- `/change_arm_ctrl_mode`
 - 类型：`kuavo_msgs/changeArmCtrlMode`
 - 描述：切换手臂控制模式
 - 参数：
 - `control_mode`: 控制模式（2表示外部控制模式）

## 4. 使用指南

### 4.1 功能概述

通过键盘按键实时控制机器人手臂末端执行器的位置：
- 位置控制：
 - W/S：前后移动
 - A/D：左右移动
 - Q/E：上下移动
- 手部控制：
 - H：抓取（关闭手掌）
 - K：松开（打开手掌）

### 4.2 主要步骤

1. **初始化**：
 - 启动仿真环境
 - 启动逆解节点
 - 切换到外部控制模式

2. **位置获取**：
 - 尝试从tf获取当前手臂末端位置
 - 如果无法获取则使用默认位置

3. **实时控制**：
 - 通过键盘输入控制手臂位置
 - 发布位姿命令到逆解节点
 - 控制手部开合（仅实物）

### 4.3 注意事项

1. 启动顺序必须按照步骤进行
2. 移动步长建议在0.01-0.05之间
3. 确保目标位置在工作空间内
4. 手部开合功能仅支持实物机器人

## 6. 常见问题

1. **无法获取tf信息**
 - 确保仿真环境已正常启动
 - 检查tf树是否完整
 - 等待几秒钟让tf信息完全发布

2. **手臂不响应控制**
 - 检查是否成功切换到外部控制模式
 - 确认当前选择的手臂是否正确
 - 验证步长是否合适

3. **手臂运动不稳定**
 - 尝试减小步长
 - 检查IK求解参数是否合适
 - 确保目标位置在工作空间内
