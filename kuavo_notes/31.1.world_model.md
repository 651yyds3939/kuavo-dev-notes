## 第 0 章：工程定位与当前结论（必读）

### 0.1 这是什么（用户曾问：到底是强化学习还是世界模型？）

**是 Model-Based RL / 世界模型，不是纯 PPO。**

* **算法**：TD-MPC2 = 隐式世界模型（encoder / dynamics / reward / Q / termination / constraint）+ 策略先验 π；可选 MPPI 在潜空间规划。
* **每次 `agent.update()` 真正在训的网络**（`world_model.py`）：

| 模块 | 学什么 |
|------|--------|
| `_encoder` | 观测 → 潜变量 z |
| `_dynamics` | z + a → 下一 z（**动力学**） |
| `_reward` | 预测奖励 |
| `_termination` / `_constraint` | 预测倒地 / 违规 |
| `_Qs` | 价值 |
| `_pi` | 潜空间策略先验（不是 PPO 的 on-policy policy gradient） |

* **训练时**：默认 `mpc=False`，用 `encode→pi(z)` 采集；观感像「策略直接出动作」，所以容易误以为是纯 RL。
* **Play 时开 `--mpc`**：在潜空间 MPPI 想象多条轨迹选优——这才是和 PPO 差别最大的地方。
* **一句话**：外层像 RL（Isaac 采数据），内层学的是「预测环境 + 在模型里改策略」= **model-based RL**。
* **与 PPO 包边界**：PPO 在 `leju_robot_rl`，本对话/本笔记主线是 `leju_robot_wm`；PPO 只作对照，不作默认答案。

### 0.2 当前硬结论（2026-07-15 / v3 之后）

1. **直接从零训舞蹈（115 维）曾全面失败**：`termination_rate≈0.7–0.8`，play 约 1–2s 倒地。
2. **直接训行走（87 维）同样失败**：同样秒倒。
3. **改成课程「先站稳」后**，仍多次失败（`wm_stand_v1/v2/v3`），**play 从未稳定存活超过约 1 秒**。
4. **已修过多处真实程序 bug**（`updates_per_iter`、双重 `action_scale`、终止过严、视频提前截断等），但 **v3 在修完后仍秒倒** → 不只是「再训几轮」的问题。
5. **v3 TensorBoard 关键证据**：
   * 训练期平均 episode 约 **70 步 ≈ 1.4s**；
   * 零动作预热阶段平均也只有约 **130 步 ≈ 2.6s**（正常应接近 `time_out=1000`）；
   * `pi_grad_norm≈0.005`，策略几乎没学到；
   * TB 里旧的 `train/termination_rate` **曾被 constraint 统计覆盖**，会误导判断。
6. **在重训任何 stand 之前，必须先跑 `--zero_action` 基线**：若零动作也秒挂，是环境/物理/接触问题；若零动作能站、策略秒倒，才是算法/数据问题。

### 0.3 文档原则

* 只记本仓 TD-MPC2 / World Model。
* 不把 PPO 训练流程写进主链路（PPO 另有文档与 `leju_robot_rl`）。
* 命令以 **当前代码** 为准；旧笔记里 `action_scale=0.30`、训练默认 MPPI 等已过时。

## 第 4 章：WM 课程路线 stand → walk → dance

用户明确要求：**先站稳，再行走，最后跳舞**（不要本末倒置去先啃全身舞）。

### 4.1 设计意图

```text
Stage1 Stand (87) ──resume──▶ Stage2 Walk (87)
                                    │
                                    ✖ 维度不通
                                    ▼
Stage3 Arms dance (115, 新训) ──resume──▶ Stage4 Full dance (115)
```

### 4.2 Stage 1 Stand 环境要点（`tdmpc2_stand_env_cfg.py`）

* 速度命令全 0；关闭速度跟踪 / feet_air_time 奖励。
* 加强 `flat_orientation_l2=-6`、`base_height=-4`（目标高 0.85）。
* `joint_pos.scale=0.25`（与 PPO flat 一致；action=0 → 默认站姿）。
* 关闭 DR / push。
* Reset：近零位姿扰动，**初速度全 0**，关节 `position_range=(1,1)`。
* 终止：`dof_pos_illegal=None`；`base_contact` 阈值 **25N**（原 1N 过敏）。

### 4.3 Stage 1 Runner 要点（`KuavoS42StandTDMPC2RunnerCfg`）

* `obs_profile=velocity`，`experiment_name=.../tdmpc2_stand`
* `seed_iterations=80`，`seed_action_mode=zero`（用零动作灌名义站姿轨迹）
* `action_scale=1.0`（bridge 不再二次缩放，见第 10 章）
* `updates_per_iter=0` → auto（`transitions//batch_size`，cap 384）
* `reward_coef=0.5`，`max_iterations=3000`，`init_at_random_ep_len=False`
* Play cfg：`mpc=False`

### 4.4 成功判据（原计划）

| 阶段 | 目标 |
|------|------|
| Stand | `env_term` 低；play `first_done_step` 大（理想接近 video_length）；`termination` 相关指标改善 |
| Walk | 能跟速度、不秒倒 |
| Dance | 能跟 CSV，不秒倒 |

**现状**：Stage1 尚未达标，不要进入 Stage2/3/4。

## 第 6 章：断点续训（Resume）

### 6.1 行为说明（重要）

`--resume` **只加载模型权重**（`model_*.pt`）：

| 会恢复 | 不会恢复 |
|--------|----------|
| 世界模型 + π 权重 | CPU replay buffer（新 run 为空） |
| | optimizer 状态 |
| | iter / global_step（从 0 再跑到 `max_iterations`） |
| | 原 TensorBoard（新建 log 目录） |

这是「加载权重继续训」，不是 PPO 那种完整断点。

### 6.2 同任务续训示例

```bash
python scripts/tdmpc2/train.py \
  --task Legged-Isaac-Velocity-Flat-Kuavo-S42-Stand-TDMPC2-v0 \
  --headless \
  --run_name wm_stand_v3_resume \
  --wm_num_envs 2048 \
  --max_iterations 3000 \
  --resume \
  --load_run 2026-07-14_20-44-07_wm_stand_v3 \
  --checkpoint model_800.pt
```

* `--load_run`：该 experiment 下的**文件夹名**（不是全路径）。
* 路径拼接：`logs/tdmpc2/<experiment_name>/<load_run>/<checkpoint>`。
* 跨 experiment：用 **绝对路径** `--checkpoint /full/path/to/model_xxx.pt`。

### 6.3 何时不该 resume

* 修了 `action_scale` / obs 维 / 网络结构之后 → **必须从头训**。
* Stand 失败的旧权重 → **不要** resume 进 walk/dance 期望奇迹。


### 7.2 零动作物理基线（任何重训前必做）

```bash
python scripts/tdmpc2/play.py \
  --task Legged-Isaac-Velocity-Flat-Kuavo-S42-Stand-TDMPC2-Play-v0 \
  --headless \
  --zero_action \
  --video --video_length 600
```

* `first_done_step≈600`：默认站姿物理 OK → 问题在策略/算法。
* `first_done_step` 很小且 `reason=base_contact`：环境/接触/执行器问题 → **先修环境再训**。

### 7.3 Play 参数说明（当前 `play.py`）

| 参数 | 含义 |
|------|------|
| `--video` | 录视频；且 **不会因 done 提前停**（会录满 `video_length`，中间 env 自动 reset） |
| `--video_length N` | 最多 N 个 env step（上限，不是「保证站 N 步」） |
| `--no_mpc` | 不用 MPPI，与训练 `mpc=False` 对齐 |
| `--eval_mode` | 用策略均值；默认不加则随机采样（更接近训练） |
| `--zero_action` | 忽略 checkpoint，始终 action=0 |

终端关键字段：

```text
Episode ended at step XX (~Ys sim). reason=base_contact|...
Eval metrics: {steps, first_done_step, num_resets, mean_reward}
```

### 7.4 视频相关踩坑（真实发生过）

#### A. 完全没视频 / FileNotFoundError

**原因**：task 与 checkpoint 路径不匹配。多次把 **Stand 的 run** 写成：

* `--task ...Punch-TDMPC2-Play-v0`（115 维舞）
* `--checkpoint .../tdmpc2_dance/${RUN_DIR}/...`

而真实文件在 `tdmpc2_stand/`。`runner.load` 失败 → 一步都没跑 → 无 mp4。

**口诀**：Stand → `Stand-*-Play` + `tdmpc2_stand`；Dance → `Punch-*-Play` + `tdmpc2_dance`。

#### B. `video_length=600` 但视频不到 1 秒

**原因（已修）**：旧 `play.py` 在 `dones.any()` 时 `break`，只录了例如 **14 帧**（14×0.02s≈0.28s 仿真）。

**现在**：`--video` 时 `stop_on_done=False`，会继续到 `video_length`；看 **`first_done_step`** 才是存活长度。

#### C. 视频里「没看见倒下就挂了」

可能是：

1. `dof_pos_illegal`（踝关节 TorchScript NaN）→ 无可见倒地就 terminate（stand 阶段已禁用该终止）；
2. `base_contact` 触发后立刻 reset，镜头上像「腿动一下就闪回」；
3. 帧太少看不清。

看终端 `reason=`。

#### D. 改了环境终止，视频仍一样 → 要重训

Play **只加载旧权重**。改 cfg **不会**让旧 `model_*.pt` 突然会站。日志若仍 `first_done_step=14`、`num_resets` 很多 → 策略没变，**必须重训**。

| 标量 | 含义 | 注意 |
|------|------|------|
| `train/env_termination_rate` | **真实** env done 占比（runner 新增） | 最可信的「倒地率」之一 |
| `train/termination_rate` | 来自 `termination_statistics` | **曾被 constraint 的同名 key 覆盖**，勿单独迷信 |
| `train/total_loss` | 世界模型总损失 | 下降≠会站 |
| `train/pi_grad_norm` | 策略梯度范数 | v3 长期 ~0.005 = 几乎没学 |
| `train/buffer_size` | buffer 中 episode 条数 | 满到 `buffer_size`（如 300000）后滚动 |
| `train/updates_per_iter` | 每 iter 梯度步 | 2048 env 应为 384；若=2 则旧 bug |
| `train/fps` | 吞吐 | |

由 `env_term` 粗算平均存活步数：

```text
avg_ep_len ≈ (steps_per_env * num_envs) / (env_dones_per_iter)
         ≈ 1 / env_termination_rate   （当 env_term 按「每 transition 的 done 比例」定义时）
```

v3：`env_term≈0.014` → 平均约 **70 步 ≈ 1.4s**。

## 第 10 章：已修复的程序问题（完整清单）

### 10.1 `updates_per_iter` 过少（致命）

* **旧行为**：约 49k transitions/iter，但只有 **2** 次梯度更新。

### 10.4 Reset 初速度扰动

* Stand reset 速度全 0；PLAY 完全确定性出生。

### 10.5 终止过严

* Stand 禁用 `dof_pos_illegal`（NaN 仍被执行器清零，但不杀 episode）。

### 10.6 Play 视频提前结束

### 10.8 其它已修（对话早期）

## 第 13 章：路线反思——为什么多次训练都活不过 1 秒

### 13.1 现象

从直接跳舞 → upright → walk → stand v1/v2/v3，**play 从未稳定 >1s**。用户观感：开局就往右/后倒。

### 13.2 原因分层

**A. 程序 bug（已修，但解释了早期全军覆没）**

* 每 iter 几乎不更新世界模型；
* 动作被缩小数倍；
* 随机探索灌满倒地数据；
* 终止过严 / 指标误导。

**B. 任务与算法设定（修 bug 后仍失败的主因）**

* 双足站立是极难探索问题；未训练策略几乎只会倒。
* `mpc=False` 时没有潜空间规划帮探索，近似「用世界模型包装的弱策略学习」。
* Buffer 长期由 **1–2 秒死亡轨迹** 主导 → 学的是「怎么倒」不是「怎么站」。
* v3 显示：**连 action=0 预热平均也活不久** → 「站住」在数据层就没成立。

**C. 路线问题**

```text
原计划：WM 从零 stand → walk → dance
现实：Stage1 未过，后面全部空中楼阁
```

同机器人上 **PPO（另一仓）已能训移动/舞**，说明机器人/仿真未必「完全不能站」，而是 **当前 TD-MPC2 从零 stand 这条实现路径不成立**。

### 13.3 能否成功？

| 路线 | 评估 |
|------|------|
| 继续盲开 `wm_stand_v4/v5` 同一范式 | **不看好**，大概率仍秒倒 |
| 先 `--zero_action` 验证，再决定修环境或换范式 | **必要** |
| PPO 先站/走，WM 做规划/蒸馏/模仿 | **可行得多** |
| WM 继续，但 BC 热启动 / 长时零动作示范 / 开真 MPC | 有机会，需改训练范式 |

**结论**：不是「再训 800/3000 步就行」；**按现路线反复训练，很大概率永远活不过 1 秒。**

（开源侧「为什么差几个量级」见 **第 13.5 章**；`wm_num_envs`/内存/`seed_steps`/USD/`rough_env` 等细节见 **第 16 章**。）

## 第 13.5 章：开源对照——别人怎么做成功的

> 来源：对话中「WM 为什么干什么都不行，查开源怎么做」的完整分析。  
> **结论：不是 TD-MPC2 算法走不通，是当前移植在任务难度、训练循环、数据质量上和成功项目差了几个量级。**

### 13.5.1 官方 [nicklashansen/tdmpc2](https://github.com/nicklashansen/tdmpc2)

| 维度 | 官方 | 我们（早期失败阶段） |
|------|------|----------------------|
| 环境 | **无 contact termination** 的 infinite-horizon | `base_contact` 等，大量提前结束 |

| 采动作 | **每步 MPPI 规划**（核心） | 训练 `mpc=False`，2048 env 只用 `pi(z)` |
| 探索 | `seed_steps=5000` 在 **单 env** 有意义 | 2048×24≈49152 步/iter，`seed_steps=5000` 瞬间耗尽 |
| 更新 | 几乎每 env step 多次 update | 曾每 iter 只 **2** 次 update |

官方 [Issue #83](https://github.com/nicklashansen/tdmpc2/issues/83)：**episodic termination + 多 env 并行** 至今无成熟官方实现，需自改 buffer/rollout。

### 13.5.2 [RL Puppeteer](https://nicklashansen.com/rlpuppeteer)（人形 + TD-MPC2 真正成功案例）

```text
阶段1：MoCap 上预训练 tracking WM
阶段2：冻结 tracking WM，再训高层 puppeteer
```

* **不是**从零在 Isaac 里直接学走/舞。
* 有 termination head，planning 里 soft-truncate。
* 论文指出：没有处理好 contact termination 时，TD-MPC2 会学成**不真实动作**。

### 13.5.3 其它参考

| 项目 | 要点 |
|------|------|
| [ETH robotic_world_model](https://github.com/leggedrobotics/robotic_world_model) | Isaac Lab 四足；**RWM + MBPO-PPO 混合**，不是裸 TD-MPC2 |
| [OmniDrones TD-MPC2](https://github.com/btx0424/OmniDrones) | 无人机，无摔倒 termination；**不能**直接类比 26-DoF 人形 |
| NVIDIA Isaac Lab Spot | 官方博客用 **RSL-RL PPO**，不是 TD-MPC2 |

## 第 16 章：补充遗漏（对话里出现过的细节）

### 16.1 `wm_num_envs`：512 / 1024 / 2048

只影响 **Isaac 并行仿真数量**，不改网络结构 / batch_size。

| num_envs | 每 iter 采集（×24） | 作用 |
|----------|-------------------|------|
| 512 | 12,288 | 省内存 |
| 1024 | 24,576 | 折中 |
| 2048 | 49,152 | 采得快，RAM 压力大 |

* ✅ 单位时间仿真步更多、buffer 填更快  
* ❌ **不等于**每 iter 梯度步更多（现在 auto update 后，env 多 → updates 也多，但受 `max_updates_per_iter=384` 封顶）  
* 早期 bug 时代：无论 512 还是 2048，updates 都只有 **2** → env 再多也白采  

### 16.2 16G 内存瓶颈（比 8G 显存更紧）

内存两块：

1. **Isaac 并行**（随 `wm_num_envs`）  
2. **CPU Replay Buffer**（与 env 数无关）：`buffer_size=300000 × seq=50 × obs≈87` → obs 一项约 **5+ GB**，整 buffer 约 **7–9 GB**

```text
Isaac 2048 envs   ~6–10 GB
Replay buffer     ~7–9 GB
系统其它          ~2–3 GB
→ 16G 很容易顶满 → swap → 更慢
```

显存反而较松：buffer 故意在 CPU，GPU 只跑 batch=128。`htop` 内存 >14G 或 swap 狂涨 → 降到 **1024**。

### 16.3 `seed_steps` 在多 env 下几乎失效

* 旧设计：`seed_steps=5000` 按 **global env steps** 计。  
* 2048×24 = 49152 步/iter → **第 1 个 iter 就耗尽**随机探索。  
* 现 Stand 改用 **`seed_iterations=80` + `seed_action_mode=zero`**（按 iter 计，更可控）。

### 16.4 早期 runner 采集/更新比例（已修，必须记清）

```text
旧：采 49,152 transitions / iter，只 update 2 次（batch 128）
   → 每 iter 只「学」256 个 sample
现：updates_per_iter = min(transitions//batch_size, 384)
   → 2048 env 时 = 384
```

这是「loss 下降但永远不会站」的第一根因。

### 16.5 `rough_env_cfg.py` 曾被误改成 Punch（行走启动失败）

* 现象：训 Velocity 时 import 炸 / 配置错乱。  
* 原因：`KuavoS42RoughEnvCfg` 被误改成跳舞类；`flat_env_cfg` 仍 import Rough。  
* 修复：恢复 `KuavoS42RoughEnvCfg` + 行走速度指令范围；跳舞留在 `punch_env_cfg.py`。

### 16.6 USD 路径错误

* 机器人 USD 曾指向错误/硬编码路径；已改为  
  `os.path.join(ISAAC_ASSET_DIR, "Robots/Kuavo/biped_s46.usd")`。  
* 注意：`leju_robot_wm` 可能是 symlink，改错目录等于改错代码。

### 16.7 `--mpc` argparse 冲突

* `play.py` / `cli_args.py` 曾重复定义 `--mpc`，启动报错。  
* 已统一：CLI 用 `--mpc` / `--no_mpc`，避免双注册。

### 16.8 Play 路径笔误（真实踩过）

错误示例（缺 `/`）：

```text
logs/tdmpc2/Kuavo/s42/tdmpc2_dance2026-06-23_.../model_3000.pt
```

正确：

```text
logs/tdmpc2/Kuavo/s42/tdmpc2_dance/2026-06-23_.../model_3000.pt
```

Stand 同理必须是 `tdmpc2_stand/`，不能写成 `tdmpc2_dance/`。

### 16.9 Velocity PLAY 与训练不一致（次要）

早期分析：`Velocity-TDMPC2-Play` 未完全继承 Flat PLAY 的关 DR/关 push；训练有 DR+推力，play 可能仍有 startup DR，速度又固定向前 → 放大「开局前栽」观感。主因仍是策略没学会；Stand PLAY 已做成确定性出生。

### 16.10 SequenceBuffer 短 episode 污染

* `sequence_length=50`；更短的 episode **padding**，pad 段 `terminated/constraint` 常为 1。  
* `termination_rate≈0.73` 时平均 episode 很短 → buffer 大量「怎么倒」的序列。  
* 采样有 mask，但短失败轨迹仍主导分布。

### 16.11 跳舞 upright 硬门控副作用

* `track_punch_*_upright`：不倒才给 mimic 分 → 永远倒 → 永远拿不到 mimic → 更难学。  
* Puppeteer/PPO 多用分阶段或强 orientation 惩罚，而不是这种 hard gate。  
* 这是直接训舞失败的加重因素之一（后来改课程站稳）。

### 16.12 constraint 标签过激（数学）

```text
upright_factor = clamp((-g_z - 0.75) / 0.25, 0, 1)
fallen := upright_factor < 0.75
     ⇔ -g_z < 0.9375
```

即：**略有倾斜就会标成 constraint=1**，不是「真正躺平才标」。  
且 `tdmpc2.py` 里 `termination_statistics` 对 termination 与 constraint **各调用一次同名 key**，后者覆盖前者 → TB `termination_rate` 可能其实是 constraint 率。

### 16.13 视频录制技术细节

* `--video` 会设 `enable_cameras`，AppLauncher 加载 `isaaclab.python.headless.rendering.kit`。  
* `gym.wrappers.RecordVideo`：`step_trigger=lambda step: step==0`，`video_length` 为帧上限。  
* 旧 play 在 done 时 `break` → 只有十几帧；现 `--video` 下继续跑满长度。
