## 第 0 章：一句话结论与文档地图

### 0.1 做什么 / 不做什么

| 项目 | 说明 |
|------|------|
| **做什么** | 右手侧夹固定瓶身 → 左手垂直接近触顶 → l5/l6 调平 → **cycle_ik 绕世界 Z 拧盖**（或 legacy `joint_l7`） |

|--------|------|--------|

### 0.3 当前稳定版主路径（v1.7 一句话）

```text
双爪张开 → init → YOLO 10 帧
→ 仅右手：曲肘→预瞄→插入→闭爪→(可选)微抬 5cm → 锁定 q_right_hold
```

## 第 1 章：任务背景与设计动机

### 1.1 从单臂抓取到双臂协同

单臂抓取（[`22.4.Lerobot_grasp.md`](./22.4.Lerobot_grasp.md) / `moveit_auto_grasp.py`）的设计前提是：

1. YOLO 只给出 **整瓶** 的 `(x, y)`，深度取 bbox 中心区域中值；
2. 每次只动 **一只手**，另一只手 `_freeze_inactive_arm()` 锁在 **init**（防重心前倾）；
3. 夹爪 **水平侧夹** 瓶身，闭合度 80～85，适合抓柱体，**不适合**拧小瓶盖。

「右手抓瓶 + 左手拧盖」需要额外解决：

| 问题 | 初版对策 |
|------|----------|
| 双臂互撞 | **分阶段时序** + **左手侧向高位避障路径** + 空间分区 |
| 瓶盖太小 YOLO 检不到 | **几何推算**：瓶盖 = 视觉瓶身点 + 标定偏移 + 瓶高常量 |
| 夹爪比瓶盖宽 | 左手 **垂直接近 + effort 触顶 + 渐进夹紧 + cycle_ik 绕世界 Z 拧盖**，不侧夹瓶盖 |
| 质心前倾 | 工作空间拒绝 + 分阶段 + 实机有人扶 |
| 收手扫桌 | **禁止**直接 `execute_dual_arm_init_home`；改用 vla **大鹏展翅** 后 init |

### 1.2 为何首版不用 LeRobot / 不用 YOLO 检瓶盖

| 方案 | 不首用的原因 |
|------|--------------|
| YOLO 检瓶盖 | ROI 极小、遮挡多、与瓶身 bbox 重复标注成本高 |
| LeRobot 模仿学习 | 需先有一条 **可重复、安全** 的规则专家轨迹；本脚本即专家策略 v1 |
| MoveIt 双臂 OMPL | URDF 手臂无 collision mesh；v1 用规则 IK + 时序防撞更可控 |

固定瓶型 + 几何推算 + 小步触顶，在 ±5mm 量级通常够用；换瓶型只需重标 `cap_offset_*` / `bottle_cap_rise_m`。

## 第 2 章：整体架构与代码关系

### 2.1 系统拓扑

```text
┌─────────────────────────────────────────────────────────────┐
│  上位机 Orin：相机 + YOLO → /vla/yolo_target (瓶身 xy)      │
└───────────────────────────┬─────────────────────────────────┘

│  下位机 NUC：bimanual_unscrew.py                             │
│    阶段 A  run_right_grasp_hold()   ← 复用 moveit_auto_grasp │
│    阶段 B  run_left_unscrew()       ← 侧向避障 + 触顶 + 拧盖  │
│    收手    execute_bimanual_safe_return() ← vla 大鹏展翅     │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 与 `moveit_auto_grasp.py` 的关系

| 模块 | 来源 | 说明 |
|------|------|------|
| 视觉 10 帧采点 | `mag._collect_vision_targets_tf2_style()` | 与单臂相同 |
| 右手 TCP / IK / 曲肘 / 水平插入 | `mag._solve_pose_ik`、`mag.execute_single_pose` | 阶段 A |
| 双臂 init 归位 | `mag.execute_dual_arm_init_home()` | 仅流程首尾 / abort |
| 左手瓶盖 IK | **本脚本** `solve_left_ik_holding_right()` | 右手 seed 保持抓握，**不** reset init |
| 左手阶段轨迹 | **本脚本** `execute_hold_right()` | 14 轴下发，**强制右手关节不变** |
| 安全收手 | **本脚本** `execute_bimanual_safe_return()` | 肩膀外摆 75°，见 [`28.moveit_grasping.md`](./28.moveit_grasping.md) |
| 夹爪 | `claw_safe.py` | 限幅 / 堵转保护 |
| 轨迹下发 | `/kuavo_arm_target_poses` | 与单臂相同 |

**禁止** 与 `kuavo_moveit_bridge.py` 同时运行（同 [`moveit_grasp.md`](./moveit_grasp.md)）。

### 2.3 与单臂 `_freeze_inactive_arm` 的关键差异

单臂 `moveit_auto_grasp.py` 中：

```python
# 非活动臂锁在 init_angles，防止双手同时前伸
frozen[inactive_slice] = init[inactive_slice]
```

双臂脚本中：

| 阶段 | 活动臂 | 锁定臂 | 锁定构型 |
|------|--------|--------|----------|
| A 右手抓瓶 | 右手 | 左手 | init（经 `_freeze_inactive_arm`） |
| B～D 左手拧盖 | 左手 | 右手 | **`q_right_hold`（抓瓶+微抬后的关节角）** |

因此 B～D 阶段必须用 `execute_hold_right()`，**不能**再用单臂的 `_freeze_inactive_arm(False)` 逻辑锁右手。

## 第 4 章：坐标系：视觉点 vs TCP 抓点 vs 瓶盖推算

### 4.1 三套坐标，切勿混用

| 名称 | 变量 | 来源 | 用途 |
|------|------|------|------|
| **视觉点** | `raw_x, raw_y` | YOLO/TF2 10 帧中值 | 工作空间检查；**瓶盖 XY 推算** |
| **右手 TCP 抓点** | `bottle_x, bottle_y` | `right_locked_xy(raw)` | **仅**右手 IK 抓瓶身 |
| **瓶盖中心** | `cap_x, cap_y, cap_z` | `compute_cap_target(vision_x, vision_y, z)` | **仅**左手接近/触顶/拧盖 |

### 4.2 典型实机数值（帮助理解偏差）

某次实机日志：

| 量 | X | Y |
|----|---|---|
| 视觉 `raw` | 0.489 | **-0.016** |
| 右手 TCP 抓点 | 0.467 | **+0.039** |
| 若错误地用 TCP 当瓶盖 | 0.467 | **+0.039** |

右手抓点在 Y 上比视觉点 **偏左约 5.5cm**（`tcp_offsets_for_arm` + `extra_y` 叠加）。若左手瓶盖也用这个 Y，左手会伸到 **右手夹爪同一侧**，极易碰撞。

**v1.2+ 规则**：`run_left_unscrew(..., raw_x, raw_y, ...)`，**不用** `bottle_x, bottle_y`。

### 4.3 瓶盖 3D 推算公式

```text
cap_x = vision_x + cap_offset_x_m
cap_y = vision_y + cap_offset_y_m
cap_z = bottle_z + bottle_cap_rise_m    # 默认 bottle_z=0.385, rise=0.12 → cap_z≈0.505
悬停高度 hover_z = cap_z + cap_hover_m  # 默认 +3.5cm → ≈0.540
高位 high_z   = hover_z + left_high_approach_m  # 默认 +10cm → ≈0.640
```

### 4.4 标定方法（固定一种水瓶，做一次）

1. 右手抓稳瓶身（或人工扶瓶）；  
2. 目视/尺子量「视觉检测点 → 瓶盖中心」的水平偏移与竖直高度；  
3. 写入 ROS param：`~cap_offset_x_m`、`~cap_offset_y_m`、`~bottle_cap_rise_m`。

**不要** 用 `TCP_OFFSET_Y_RIGHT` / `right_tcp_extra_y_m` 去修瓶盖 XY — TCP 修的是 **夹爪落点**，修不了「bbox 中心 ≠ 瓶盖中心」。

### 4.5 左手瓶盖落点微调 `left_tcp_extra_*`（v1.7 实机标定）

在 `compute_cap_target` 得到瓶盖中心后，**叠加 MoveIt 左手 TCP 标定**（`mag.tcp_offsets_for_arm(True)`）与下列 extra。

**v1.7 当前默认**（见 `bimanual_unscrew.py` `DEFAULTS`，实机标定后勿随意改回）：

| 参数 | 默认 | 方向（`base_link`） |
|------|------|---------------------|
| `left_tcp_extra_x_m` | **-0.040** | 负=后 -X；偏前则减小（更负），偏后则增大 |
| `left_tcp_extra_y_m` | **+0.025** | 正=左 +Y；偏左则减小，偏右则增大 |
| `left_tcp_extra_z_m` | **-0.010** | 负=降 Z；偏低则增大（更接近 0 或为正），偏高则减小 |

**2026-06～07 标定历程**（阶段 C 前只动本三项，勿与 l5/l6 同时改）：

| 轮次 | 参数 (x, y, z) | 现象 / 结论 |
|------|----------------|-------------|
| 初版 v1.6 | -0.010, +0.035, -0.006 | 基线 |
| 误调 | -0.100, +0.038, -0.045 | 严重偏左/偏上 |
| 实机 1 | -0.050, +0.015, -0.030 | 直连 IK 成功，流程跑通 |
| 实机 2 | -0.050, **+0.050**, -0.030 | Y 再补偿 5cm 后左手对准更好 |
| 实机 3 | **-0.040**, +0.050, -0.030 | X 微调后基本抓准瓶盖 |
| 实机 4（Jul 6 固化） | **-0.040, +0.025, -0.010** | Y 从 +0.050 回调；Z 略降 |
| **v1.7 代码默认（用户锁定）** | **-0.040, +0.025, -0.010** | `DEFAULTS` 100–102 行；**勿擅自改回** |

> **🔒 用户实机锁定（2026-07-06～07）**：下列参数经多轮实机验证，**禁止在未经用户确认的情况下修改**——`left_tcp_extra_x/y/z_m`、`left_cap_wrist5/6_bias_rad`。若需微调，仅通过 ROS 启动参数 `_left_tcp_extra_*:=...` 覆盖，改完须用户复测再写回 `DEFAULTS`。

**`left_cap_yaw_decouple_extra:=true`（默认）**：`extra_x/y/z` **只平移 IK 目标**，不参与 yaw 计算。否则 `extra_x` 会通过 `atan2` 耦合进姿态，出现「调了 x 不动」的假象。日志核对：

```text
🎯 瓶盖 X 链: geom_x=0.494 + tcp_x=-0.013 + extra_x=-0.040 → IK_x=0.440 (yaw_ref_x=0.481 decouple=True)
```

调参步长 **±0.002m**；启动日志核对 `left_extra=(x,y,z)` 与 `瓶盖落点`。

日志关键字：

```text
🎯 瓶盖落点(+左手TCP -0.013,0.004 +extra): (0.419, -0.014, 0.509)
```

**调参纪律**（2026-06 末实机结论）：

1. **阶段 C 完成前**只动 `left_tcp_extra_*`，不要同时改 l5/l6、指尖 TCP、roll_extra。  
2. 瓶位每次差 3cm（YOLO Y 漂移）会导致「同参数一次偏高一次正常」——**贴胶带固定瓶位**可显著降方差。  
3. 仅右指碰盖、左指悬空 → 优先 **+Y（往左）** 与 **-X（往后）**；闭合时 `effort≈0` 说明 XY 仍未对准。  
4. 粗定位 OK 后，高度用 `left_tcp_extra_z_m` 或 effort 触顶闭环，不要只靠 `contact_z_stop_above_m` 硬停。

`cap_reference_mode` 默认 **`right_grasp`**（瓶盖 XY = 右手抓点 + `cap_from_grasp_*`）；抓后重采视觉默认 **关**（`cap_re_vision_after_grasp:=false`，倾斜瓶身时 YOLO 漂移反而破坏 XY）。

## 第 7 章：左爪触顶、调平、闭合与拧盖

### 7.1 左臂关节语义（实机确认，必读）

| 关节 | 索引 | 作用 | 本脚本用法 |
|------|------|------|------------|
| **zarm_l5** | 4 | 小臂+腕部整体旋转，**调平主自由度** | `left_cap_wrist5_bias_rad` 触顶后叠加 |
| **zarm_l6** | 5 | 夹爪俯仰/上下倾，**调平辅** | `left_cap_wrist6_bias_rad` |
| **zarm_l7** | 6 | 水平时绕夹爪 **z 轴**旋转 | **仅** legacy `joint_l7` 拧盖；cycle_ik 由全臂 IK 绕世界 Z 补偿 |

**禁止**用 l7 做触顶调平；**禁止**在 IK 目标 quat 上大幅加 roll（`left_cap_base_roll_extra_rad` 曾导致 IK 无解）。调平只动 l5/l6，且 `left_level_bias_contact_only:=true` 时 **接近/下降 IK 不加偏置**，仅触顶停稳后叠加。

v1.6 初版调平偏置 = 实机值的 **65%**；v1.7 在实机迭代中 **l6 逐步加大** 以修「前高后低」：

| 参数 | v1.6 默认 | v1.7 历程 | **v1.7 当前默认** |
|------|-----------|-----------|-------------------|
| `left_cap_wrist5_bias_rad` | **-0.250 (-14.3°)** | 保持 | **-0.250 (-14.3°)** |
| `left_cap_wrist6_bias_rad` | -0.023 (-1.3°) | -0.055 → -0.142 → **-0.300** | **-0.300 (-17.2°)** |

**l6 语义**：更负 = 夹爪前端下压（修前高后低）；触顶后日志 `📐 触顶调平 l5=... l6=...` 核对是否生效。

无相机复现触顶构型：见 **§7.6** `left_cap_level_tune.py`。

### 7.2 触顶搜索 `descend_until_contact`（v1.6 effort_first）

**旧版 bug（已修）**：下降时左爪 **全开**，`/leju_claw_state` effort 永远无触顶反馈；脚本却在 `cap_z + stop_above` 处 **几何硬停**，导致「偏高、无 effort、空夹」。

**v1.6 默认 `contact_mode:=effort_first`**：

```text
悬停 → 半夹 left_contact_preclose_pos=35
     → 小步纯 Z 下降（2mm/步，最多 25 步）
     → 左爪 effort ≥ contact_effort_threshold(0.28) → 停
     → 否则过软参考高度后再探 contact_extra_descend_steps 步
     → 硬下限 cap_z - contact_z_max_below_cap_m(6mm)
     → l5/l6 触顶调平
```

| 参数 | v1.6 默认 | 含义 |
|------|-----------|------|
| `contact_mode` | `effort_first` | 半夹+effort 闭环；`geometry_only` 恢复旧几何硬停 |
| `contact_preclose_before_descend` | `true` | 下降前先半夹，否则 effort 无效 |
| `contact_step_m` | `0.002` | 每步 2mm |
| `contact_max_steps` | `25` | 最多步数 |
| `contact_effort_threshold` | `0.28` | 半夹触顶阈值（原 0.55 过高） |
| `contact_z_stop_above_m` | `0.003` | **软参考** cap_z+3mm，非硬停 |
| `contact_z_max_below_cap_m` | `0.006` | 硬安全：最多低于推算 cap_z 6mm |
| `contact_extra_descend_steps` | `6` | 过软参考仍无 effort 时再试步数 |

成功日志：

```text
🖐️ 触顶搜索前左爪半开 (pos=35)，effort 触顶闭环已启用
✅ 左爪触顶 (effort≥0.28) @ z=0.515 (cap_z=0.509 Δz=+0.006)
```

仍 `⚠️ 未检测到触顶 effort` → 优先修 **XY**（`left_tcp_extra_*`），再降 `_contact_effort_threshold:=0.18` 或增大 `_contact_z_max_below_cap_m:=0.010`。

**v1.7**：`descend_until_contact` 返回 **实际触顶 Z** `contact_z`（写入 `meta["contact_z"]`），供拧盖使用真实高度，而非 `cap_z + contact_z_stop_above_m` 推算值。

### 7.3 指尖 TCP 补偿（可选，默认关）

MoveIt 末端 `zarm_l7_end_effector` ≈ **爪中心**；Leju 爪无手指 link，外缘指尖需额外补偿。URDF 与 `/leju_claw_state` 分离，开合角改变指尖相对 EE 位置。

| 参数 | 默认 | 说明 |

| `left_claw_tip_enable` | **`false`** | 未标定前关闭 |
| `left_claw_tip_mode` | `world_z` | 只沿竖直补偿，**不引入侧倾** |

| `left_claw_tip_mode=ee` | — | EE 系向量 `[dx,dy,dz]`，水平姿态下易致前高后低，需实机标定 |

### 7.4 左爪夹紧：`close_left_cap_gradual`（v1.7）

| 版本 | close / effort | claw_safe 上限 | 现象 |
|------|----------------|----------------|------|

| 层 | 来源 | 典型量级 |
|----|------|----------|
| 1 | YOLO bbox ≠ 瓶盖中心；**瓶位不固定** | ±5～30mm |
| 2 | 右手抓后瓶身微移/倾斜 | ±2～5mm |
| 3 | 几何 cap_z（`bottle_cap_rise_m` + 微抬 scale） | ±3～10mm |
| 4 | MoveIt EE ≠ 指尖；爪开合改变接触点 | ±5～15mm |
| 5 | IK 解姿态 + 触顶后 l5/l6 与 quat 目标不一致 | 水平/侧倾 |

#### 7.7.2 推荐调参顺序（v1.7）

```text
A. right_tcp_extra_*     → 右手后端抓瓶（x 往前、y 微调）
B. left_tcp_extra_y/x/z  → 左手 XY/Z 对准（±2mm 一档；见 §4.5 标定表）
C. effort 触顶 / contact_z → 日志出现触顶或记录 contact_z
D. left_cap_wrist5/6     → 调平（l6 修前高后低；当前默认 l6=-0.300）
E. left_cap_close_*      → 渐进夹紧（等到位 + 终压）
F. left_cap_twist_cycles → 拧盖（默认 skip_align + use_contact_yaw）
```

**不要**在 C 完成前同时改 D/E 与指尖 TCP。

#### 7.7.3 现象 → 参数速查

| 现象 | 优先调 |
|------|--------|
| 总偏左/偏右/偏前/偏后 | `left_tcp_extra_y_m` / `left_tcp_extra_x_m` |
| 偏高/偏低 | `left_tcp_extra_z_m`；或 effort 触顶 Δz |
| 仅右指碰盖 | +Y 往左、-X 往后（本机 +3cm/-1cm 量级） |
| 左高右低 / 左低右高 | `left_cap_wrist5/6_bias`（±10% 一档） |
| 闭合到 75 但 effort≈0 | XY 未对准，非 close 不够 |
| 渐进闭合 service failed | 指令发太快；需 `left_cap_close_settle_sec` 等到 Reached |
| 命令 98 反馈 pos≈58 | 同上；见 §7.4 踩坑 |
| 拧盖 IK 无解 @朝右基准 | v1.7 默认 `use_contact_yaw` + `skip_align` |
| 同参数两次高度不一 | 固定瓶位；看 YOLO Y 是否漂移 |
| 连续跑不一致 | 开环 cap_z + 视觉方差；靠 effort 闭环减 Z 误差 |

`cap_xy_refine_enable` 默认 **关**（9 点×IK 仍慢且 effort 常无效）。

## 第 8 章：防碰撞、质心与 WBC 局限

### 8.1 时序防撞（首版核心）

| 规则 | 说明 |
|------|------|
| A 完成前 | 左手保持 init，不前伸 |
| B～D | 右手锁定 `q_right_hold`，不再规划 |
| 禁止 | 双臂同时从远处插向瓶心 |

### 8.2 空间分区

```text
        左臂区（上/左）          右臂区（右/中）
              ↓                      ↓
         垂直接触瓶盖            水平侧夹瓶身
              \                    /
               \    瓶 + 盖      /
                \      |        /
                 ─── 桌面 ───
```

建议瓶子放在 **机器人右前方**（YOLO `Y ≤ 0.05`）。

### 8.3 MoveIt 碰撞（v1 局限）

- 左手 IK：`avoid_collisions=False`（与经典抓取一致）；
- URDF 手臂 **无 collision mesh**；
- v1 **未** attach 瓶体到右手 link。

**实机**：低速、有人监护、急停就绪。

### 8.4 WBC 质心（与单臂相同，双臂更严）

控制链路：

```text
/arm_traj_change_mode(2)  →  external_control
/kuavo_arm_target_poses   →  humanoid_Arm_time_target_control
                         →  /humanoid_mpc_target_arm → MPC + WBC
```

脚本侧对策：

1. **分阶段** — 仅 A 动右手，B～D 再动左手；  
2. **工作空间拒绝** — 默认 `bottle_x_max_m=0.55`（单臂 YOLO 上限 0.65 **更严**）；  
3. **实机监护** — 阶段 B 起有人扶。

观测质心：

```bash
rostopic echo /humanoid_controller/com/r -n 1
rostopic echo /humanoid_controller/com/r_des -n 1
```

### 12.2 FAQ

**Q：能否瓶子放左边、仍用本脚本？**  
A：可以跑，但右手从右侧够左侧瓶身时易与左手重叠；**建议 YOLO Y≤0.05（偏右放）**。

**Q：YOLO 要不要改检瓶盖？**  
A：v1 **不需要**。固定瓶型用几何推算 + 触顶更稳。

**Q：测试模式用什么参数跳过拧盖？**  
A：v1.7 默认 **cycle_ik**，请设 **`_left_cap_twist_cycles:=0`**（日志：`只测接近+触顶+轻夹`）。`_twist_steps:=0` **仅** legacy `joint_l7` 模式有效。

**Q：为什么左爪一直张开（旧日志）？**  
A：v1.0～v1.1 在 `twist_steps=0` 时误跳过闭合；**v1.2+ 已修复**。请更新脚本重跑。

**Q：左爪闭合了但开口仍很大 / effort≈0？**  
A：先看 **XY 是否对准**（仅右指碰盖 → 调 `left_tcp_extra_y/x`）。对准后仍松：v1.7 默认 **98 / 1.0** 渐进闭合（≤ `claw_max_close_pos=98`、`claw_max_close_effort=1.2A`，见 [`接口使用文档.md`](../../docs/4开发接口/接口使用文档.md)）。若日志成片 **`service failed: b''`** 且 fb pos 卡 ~58 → 不是限幅问题，是 **未等到 Reached**（§7.4）。

**Q：命令 close=98 但反馈 pos 只有 58？**  
A：驱动在 **Moving** 中拒收新指令。增大 `left_cap_close_settle_sec`（默认 2.5s）；每步须 `_call_left_claw_close_step` 等到 state=Reached(2)。

**Q：夹紧后报「对准朝右基准 IK 无解」？**  
A：v1.6 夹紧后强制 -90° 对准导致。v1.7 默认 **`use_contact_yaw` + `skip_align`**；日志应见 `▶️ 沿用触顶姿态直接拧盖`。仍失败可 `_left_cap_twist_mode:=joint_l7`。

**Q：末端能否绕瓶盖做圆周运动？**  
A：**cycle_ik** 已是「盖心为轴、TCP XYZ 固定、姿态绕世界 Z 转」。若需 XY 平面 **真走圆弧**，属 v2 **`orbit_ik`**（代码中 `_twist_orbital_ik` 骨架，未默认启用）。

**Q：哪些参数不能擅自改？**  
A：用户实机锁定：`left_tcp_extra_x/y/z_m`（100–102 行）、`left_cap_wrist5/6_bias_rad`。改补偿前须用户复测确认。

**Q：未检测到触顶 effort 怎么办？**  
A：v1.7 默认半夹后再降。仍无 effort → 优先修 **XY** 与固定瓶位，再降 `_contact_effort_threshold:=0.18` 或增 `_contact_z_max_below_cap_m:=0.010`。勿只靠降低 `contact_z_stop_above_m` 硬停（易偏高空夹）。

**Q：拧不动怎么办？**  
A：cycle_ik 下增 `_left_cap_twist_cycles`（默认 4×90°）；略增 `left_cap_close_pos`；检查盖是否过紧。legacy 模式才调 `twist_steps`。

**Q：报「瓶 X 过远」？**  
A：默认 `_bottle_x_max_m:=0.55` 故意比单臂严。移近瓶子或 `_bottle_x_max_m:=0.60`（需有人扶）。

**Q：XY 精搜像死循环？**  
A：旧版默认 25 点×2 次 IK≈40s。v1.5+ **默认关闭** `_cap_xy_refine_enable`；开启时仅 3×3、限时 12s，Ctrl+C 可中断。日志 `effort=-0.01` 表示精搜无效，应改 `cap_offset` 而非开精搜。

**Q：Ctrl+C 后机器人不回来？**  
A：Ctrl+C 会触发 `🛑 紧急收手` + 大鹏展翅。若 rospy 已 shutdown 导致指令失败，用 **§12.0 手动收手**。运行中不要连按两次 Ctrl+C。

**Q：异常中止时手臂扫桌？**  
A：v1.4 已修：`safe_abort()` 若 `q_right_hold` 存在或构型远离 init，**强制** `execute_bimanual_safe_return()`，不再直跳 init。日志应见 `双臂前伸态 → vla 大鹏展翅安全收手`。

**Q：右手没抓到但脚本仍继续？**  
A：v1.4 闭爪后 `verify_right_grasp()` 检查右爪 pos≥55、effort≥0.35；失败则中止并进安全收手。可调 `_right_grasp_min_effort:=0.30` 若瓶身较细。

**Q：左手 IK 无解后扫桌？**  
A：同 abort 修复；另左侧高位 IK 失败时会 **自动减小 lateral 重试**，仍失败则 **跳过** 直试瓶前高位。瓶 Y 过负（如 -0.13）易触发 IK 极限，建议把瓶移回第一次成功位置附近（Y≈-0.09）。

**Q：为什么同参数两次高度不一样？**  
A：YOLO Y 帧间可漂 3cm+，开环 `cap_z` 可能相同但落点不同。**贴胶带固定瓶位**；阶段 C 前只调 `left_tcp_extra_*`。

**Q：调平后仍左低右高 / 左高右低？**  
A：7-DOF 冗余下水平调平是多关节耦合；触顶后 l5/l6 与 IK quat 冲突。用 **65% 偏置** 起步 + `left_cap_level_tune.py` 微调；v2 可考虑约束 IK / 零空间调平。

**Q：和 22.4 LeRobot 冲突吗？**  
A：不冲突。本脚本是 **独立终端 8**；采数仍用 `lerobot_data_harvester.py` + `moveit_auto_grasp.py`。

**Q：为什么日志里右手 Y=0.039 而视觉 Y=-0.016？**  
A：正常。前者是 **TCP 抓点**，后者是 **YOLO 视觉点**；瓶盖推算用后者（§4）。

### 15.1 视觉升级：从几何推算到 HSV 直接检测

```
           ↑                    ↑
      瓶型不同就错         右手抓后瓶子微倾就错
```

无论怎么调 `left_tcp_extra` 和 `cap_offset`，几何推算的基线就是有误差的。上位机已有 YOLO + 深度图 + TF2 变换能力，直接检测瓶盖比几何推算优越得多。因此委托上位机 Claude（SSH `leju_kuavo@192.168.26.12`）完成 HSV 蓝色瓶盖检测功能。

#### HSV 检测工作原理

### 15.2 Z 轴策略：硬编码 vs 视觉 Z 的权衡

#### 历史渊源

早期 `auto_grasp.py` 时代（见 4.4real_visual_grasp.md §2.1, §3.1）：
- 硬编码时期：相机深度 Z ≠ base_link 高度（无 TF2 正确变换），直接将深度 Z 喂给 IK 导致 "抓天花板" 报错
- TF2 时期：TF2 解决了坐标系变换，但**深度图边缘噪点**导致 Z 坐标剧烈跳动 → IK 频繁无解
- 工程决策：**取 XY（相对可靠），Z 硬编码锁死**。这在整个项目中始终沿用

#### v1.8 决策

经过实机验证，HSV 瓶盖 Z 确实存在深度噪点问题（小物体边缘）。继续采用保守策略：

| 坐标 | 右手抓瓶 | 左手拧盖（HSV路径） |
|------|----------|-------------------|
| X | 上位机 + 补偿 | **HSV 直接检测** |
| Y | 上位机 + 补偿 | **HSV 直接检测** |
| Z | **硬编码 SAFE_LOCKED_Z=0.385** | **几何推算（稳定）** |

- HSV Z 有深度噪点风险（瓶盖仅 ~3cm 直径，边缘几个像素可能测到背景）
- 几何 Z 虽不够泛化（瓶型不同偏差 1-2cm），但在 effort 触顶闭环可补
- 硬编码 Z **保证 IK 永远不失败**——此前实测视觉 Z 频繁导致逆解失败

#### 右手硬编码对左手的影响

右手 `locked_z = SAFE_LOCKED_Z + right_grasp_z_offset_m = 0.355`，其偏差通过 `cap_z_lift_scale=0.2` 微弱影响左手瓶盖 Z（仅乘 0.2 比例）。HSV 路径完全跳过此计算链。

### 15.3 拧盖逻辑重构：从 IK 绕轴到轨道棘轮

#### 原方案问题

v1.7 `cycle_ik` 模式用全臂 IK 保持 TCP 同一位置绕世界 Z 旋转姿态。IK 在 15-30° 即无解：`❌ [周期1转] IK z=15.0° IK 无解`。回退 `joint_l7` 连续旋转 l7 120° 不松爪，两个手臂在瓶盖上对抗。

#### 轨道棘轮方案

新函数 `_twist_orbital_ik()` — TCP 绕瓶盖中心 (cap_x, cap_y) 做圆弧轨道运动：

- **原理**：`TCP = C + Rz(θ) × full_off`（full_off = tcp_off + left_extra），每步姿态也绕 Z 转对应角度
- **轨道半径** = `|left_tcp_extra + tcp_off|`，由现有参数自动确定（~6cm）
- **每步 Δ**：15° → TCP 移 ~1.6cm, 姿态转 15° — IK 小步求解
- **返回阶段**：`start_ang=cycle_rad` 保证平滑回到 0°

**首次失败记录**：只用了 `tcp_offsets_for_arm`（-0.013, 0.004）做轨道，忘了加 `left_tcp_extra`（-0.040, 0.025），轨道半径偏小 → TCP 第一帧差 6cm → IK 无解。修复后使用 `full_off = off + extra`，数学验证通过。

#### 棘轮周期（每个周期 4 步）

```
1. TCP 绕 cap 轨道前进 cycle_deg (默认90°)  → 拧盖
2. 松开夹爪 (防回拖瓶盖)
3. TCP 反向绕 cap 回到起始位置              → 夹爪归位
4. 闭合夹爪
→ 下一周期
```

当前代码已实现，但**在补偿对准之前尚未完整测试拧盖功能**。

### 15.4 夹爪指尖补偿：4 天探索全记录

本节省略了大量重复调参日志，只保留**方案结论**和**失败根因**。

根源问题：

```text
URDF 模型手臂末端 = zarm_l7_end_effector (没有夹爪)
实际物理指尖 = zarm_l7_end_effector + 夹爪长度 (~5-6cm)
MoveIt IK 只把 end_effector 放到瓶盖坐标
→ 永远差一个夹爪长度
```

#### 方案矩阵（按探索顺序）

| # | 方案 | 原理 | 结果 | 根因 |
|---|------|------|------|------|
| 1 | **base_link 硬编码** | `left_tcp_extra_*` 在 base_link 加固定偏移 | **定点可用** | 换瓶位→手臂朝向变→固定偏移方向不对 |
| 2 | **EE 系补偿(ee模式)** | l7 系旋转偏移向量(四元数旋转) | **全部 IK 无解** | dx/dy/dz 值通过四元数旋转后大幅偏转，推出工作空间 |
| 3 | **world_z** | EE 系仅补 Z（沿世界 Z 轴上升），XY 走 base_link | **定点可用，最佳方案** | XY 仍是 base_link 固定偏移，换瓶位有偏差 |
| 4 | **XY 精搜** (`cap_xy_refine_enable`) | 悬停高度网格探 effort 找峰值 | **全程无 effort** | 精搜在调平(l5/l6 bias)前执行→夹爪斜着探不到 |
| 5 | **FK 自动补偿** | `/compute_fk` 反查 l7 真实位姿→修正 IK 目标 | **不收敛** | 修正后目标超出左臂工作空间，IK 回退 |
| 6 | **URDF 虚拟关节** | URDF 加 `left_gripper_tip` 固定关节从 l7 延伸 | **未收敛** | 手调 xyz 三个耦合值，试参数十次未命中 |

#### 为什么所有方案都在 `approach_pitch=-π/2` 构型下失败

手臂水平前伸接近桌面时已处于**关节限位边缘**。雅可比矩阵在 `pitch=-π/2 + CLAW_ROLL=-π/2` 附近接近奇异——两个旋转轴重合，丢失一个自由度。任何 >2cm 的末端平移指令都无法被剩余的关节自由度吸收。IK 数值迭代（牛顿-拉弗森）在奇异点附近直接退出。

**这不是算法问题，是物理构型限制。** 不改变手臂末端目标构型（比如让夹爪不水平，换个角度），没有方案能在代码层面根除。

#### 关于 URDF 虚拟关节

这是**正确的长期方案**，但当前手调 offset 无法收敛：
- `left_gripper_tip_joint` 从 `zarm_l7_link` 延伸，`<origin xyz="dx dy dz">` 三个值耦合
- CLAW_ROLL 旋转后 l7 的 X/Y/Z 映射到世界 X/Y/Z 不是正交的
- 调 dx 同时影响夹爪上下和前后

**正确的标定方法**：让机器人走到抓取姿态，用卡尺直接测量 l7 关节中心到夹爪指尖的物理距离（在 l7 坐标系下），而非通过 base_link 补偿反推。

### 15.5 右手抓握与左手路径优化

#### 右手验收阈值放宽

#### 瓶位限制


### 16.1 已确认的任务定义与方向

- 右手抓住瓶身并保持关节角 `q_right_hold`；左手从上方垂直接近瓶盖、触顶、夹紧并绕世界 Z 旋转。

### 16.3 动作开关的语义和实现

代码新增动作参数：

```text
_left_cap_twist_action:=tighten
_left_cap_twist_action:=loosen
```

- `tighten` 是默认值，强制将每轮角度设为负数。
- `loosen` 将每轮角度设为正数。
- 程序先取 `_left_cap_twist_cycle_deg` 的绝对值，再根据动作设置符号；因此命令行传 `15` 或 `-15` 不会绕过动作开关。
- 无效动作值报警后回退到 `tighten`。
- 启动日志必须打印 `动作模式: 拧紧 [tighten]` 或 `动作模式: 拧松（待标定） [loosen]`。
- 动作开关只改变旋转方向和拧松专用覆盖，不改变右手抓取阶段、左手路径、夹爪闭合时序和安全收手。

### 16.4 拧松模式第一次失败的根因

逆时针第一次测试使用 `loosen +15°` 时，日志出现：

```text
固定点 IK z=10.0° seed_l7=38.0° IK 无解
周期1仅规划成功约9.8°
```

这不是单纯的随机 IK 失败：

1. `seed_l7` 已达到约 `+38°` 上限，说明正向旋转的 L7/连续构型余量不足。
2. 原拧紧动态 Z 补偿 `-0.0022m/deg` 被错误复用于拧松，15° 会主动下移约 `33mm`。
3. 原拧紧动态 pitch 补偿 `-0.6deg/deg` 被复用，15° 会额外累计约 `-9°` 俯仰。
4. 左夹爪初始朝前时，逆时针受力方向让手臂更容易别住；用户实机观察到初始姿态更朝右更适合逆时针。
5. 朝右偏航后，EE 到真实指尖的 Z 映射发生变化；日志曾从约 `-14.8mm` 变为 `-29.6mm`，说明拧紧的初始 pitch 也不能机械复用。
6. 旋转中心日志中曾有配置中心与使用中心约 `25mm` 的误差；`_left_cap_twist_skip_align:=true` 会保留此实际几何误差，pivot、指尖 TCP 和瓶盖落点不能混为一谈。

第一次增加朝右偏航 `-0.35rad` 后，IK 可以完成15°，但用户继续观察到：初始夹爪位置偏高，旋转时末端往左、往下。这促成了下面的拧松独立补偿。

### 16.6 拧松模式下一步单变量标定表

一次只改一个参数，每次先测试一轮15°，然后才能测试多轮：

| 实机现象 | 只改参数 | 建议变化 |
|---|---|---|
| 初始末端仍偏高 | `_left_cap_loosen_pitch_extra_rad` | 先 `0.00`，再 `-0.05`；若方向相反试 `0.10` |
| 初始夹爪整体偏高 | `_left_cap_loosen_tcp_extra_z_m` | `-0.005 → -0.008 → -0.010`；若偏低退回 `-0.002` |
| 旋转仍向左 | `_left_cap_loosen_y_comp_per_deg_m` | 从 `0` 试 `-0.0003/-0.0005/-0.0010`；负值代表向右 |
| 旋转开始向右 | `_left_cap_loosen_y_comp_per_deg_m` | 减小负值，回到 `0` 或正小值 |
| 旋转仍向下 | `_left_cap_loosen_z_comp_per_deg_m` | `0.001 → 0.0013 → 0.0015 → 0.0020` |
| 旋转开始向上 | `_left_cap_loosen_z_comp_per_deg_m` | 降到 `0.0007/0.0005/0` |
| 正向旋转约10°又 IK 无解 | 先不要动补偿 | 先降低单轮角度、检查初始 yaw/pitch 和 L7 seed 余量；不要放宽关节安全限制 |
| 夹爪随盖打滑 | 初始 yaw/闭合/触顶参数 | 先检查朝右预偏、触顶高度和夹爪受力，不要用 XYZ 补偿掩盖打滑 |

符号解释：由于 `+Y` 是向左，逆时针过程中若观察到往左，补偿应从 `0` 往负方向试；由于 `+Z` 向上，向下沉时使用正 Z 补偿。

### 16.7 初始落点、姿态、pivot 与旋转补偿的边界

**初始落点：**

- `_left_tcp_extra_x_m`：前后；偏前减小，偏后增大。
- `_left_tcp_extra_y_m`：左右；偏左减小，偏右增大。
- `_left_tcp_extra_z_m`：上下；偏高减小，偏低增大。
- `_left_cap_yaw_decouple_extra:=true` 时，X/Y 只平移，不参与 yaw，避免“改了位置却同时转臂”。
- 拧松的 `_left_cap_loosen_tcp_extra_z_m` 是在全局左手 Z 上的额外覆盖；不要用它改拧紧。

**静态姿态：**

- `_left_cap_approach_pitch_rad` 约 `-pi/2`，是垂直接近姿态；当前已验证，通常不调。
- `_left_cap_roll_extra_rad` 是目标姿态中的局部 roll，不能直接等同于 L6/L7 关节角。
- `_left_cap_pitch_extra_rad` 影响接近、悬停和触顶阶段的基础 pitch；拧松有独立覆盖。
- `_left_cap_yaw_offset_rad` 控制水平朝向；拧松由 `left_cap_loosen_yaw_offset_rad` 叠加，负值按当前实机定义为朝右。
- `_left_cap_wrist5_bias_rad` 主调触顶后的整体水平；`_left_cap_wrist6_bias_rad` 主要调夹爪前高后低；`_left_level_bias_contact_only:=true` 可避免破坏接近 IK。
- `pitch_offset`、wrist5/6 和动态 pitch 不要同时调；先把其它调平量设为0，确认单个参数正负方向。

**旋转中心与指尖：**

- `_left_cap_twist_pivot_ee_m` 是 EE 局部坐标，不是世界坐标；当前 `[0.018,0.010,-0.0525]` 应视为已验证几何值，不能拿它直接修正世界 X/Y/Z 漂移。
- URDF 的 `zarm_l7_end_effector` 不包含真实夹爪指尖；实际指尖和模型 EE 存在约5～6cm差异。`left_tcp_extra_*` 是世界/基座补偿，`pivot_ee` 是局部旋转中心，二者不能混用。
- EE系补偿、world_z、XY精搜、FK自动补偿和虚拟夹爪关节的历史实验均存在工作空间/奇异点/不收敛问题；不要在未重新标定的情况下打开这些实验路径。

**旋转动态补偿：**

```text
目标XYZ = 基准XYZ + abs(累计角度) × [x_comp, y_comp, z_comp]
动态pitch = abs(累计角度) × pitch_comp
```

- 动态 XYZ 只修旋转中位置漂移，不修初始位置。
- 动态 pitch 只修旋转中的姿态水平，不修整体位置。
- 拧紧的 `Y=+1mm/deg、Z=-2.2mm/deg、pitch=-0.6deg/deg` 已验证，不能套到拧松。
- 拧松当前采用 `Y=0、Z=+1mm/deg、pitch=0` 作为保守起点，等待新一轮实机反馈。

### 16.8 右手抓取微调与验收

右手阶段实际抓取点为：

```text
抓取X = 视觉X + MoveIt右TCP偏移X + _right_tcp_extra_x_m
抓取Y = 视觉Y + MoveIt右TCP偏移Y + _right_tcp_extra_y_m
抓取Z = SAFE_LOCKED_Z + _right_grasp_z_offset_m
```

当前用户固化的右手 XY：

```text
_right_tcp_extra_x_m:=0.015
_right_tcp_extra_y_m:=-0.023
_right_grasp_z_offset_m:=-0.03
```

方向和微调：

- 右爪太靠前：减小 `right_tcp_extra_x_m`；太靠后：增大。
- 右爪太靠左：减小 `right_tcp_extra_y_m`；太靠右：增大。
- 右爪太高：`right_grasp_z_offset_m` 更负；太低：减小负值。
- 每次位置改 `2～5mm`，不要同时改 X/Y/Z。
- `right_hold_after_grasp` 默认 `false`；开启后由 `right_micro_lift_m` 控制抓后抬升，当前不是抓取落点微调。

右手验收参数只影响“是否放行”，不改变机械动作：

```text
_right_grasp_min_close_pos:=40.0
_right_grasp_min_effort:=0.05
_right_grasp_accept_close_pos:=70.0
```

右爪闭合位置和力度由 `claw_safe.py` 中的 `CLAW_CLOSE_RIGHT`、`CLAW_EFFORT_CLOSE_RIGHT` 控制，不要把左爪的 `left_cap_close_*` 参数当成右爪参数。

### 16.9 触顶、闭合、路径和安全参数

**触顶搜索：**

- `_left_contact_preclose_pos:=35.0`，`_left_contact_preclose_effort:=0.22`。
- `_contact_step_m:=0.002`，`_contact_max_steps:=25`，`_contact_effort_threshold:=0.28`。
- `_contact_z_stop_above_m:=0.003` 是软参考；`_contact_z_max_below_cap_m:=0.006` 是硬安全下限，通常不能随意增大。
- 触顶未检测到 effort 时，程序仍会在硬下限停止；日志中的“未检测到触顶 effort”不能当成触顶成功。

**左爪闭合：**

- `_left_cap_close_pos:=98.0`、`_left_cap_effort:=1.0`，受 `claw_max_close_pos:=98.0` 和 `claw_max_close_effort:=1.2` 限幅。
- `_left_cap_close_settle_sec:=2.5`、`_left_cap_close_retries:=4` 用于等待/重试；服务失败不等于 IK 失败。
- `left_cap_close_ramp_enable`、`left_cap_final_squeeze_enable` 默认关闭；只有确认打滑且机械安全时才启用。

**旋转轨迹：**

- `left_cap_twist_mode:=in_place_ik`、`direct_l7_enable:=false`、`seed_l7_enable:=true` 是当前固定 TCP 连续 IK 路径。
- `cartesian_max_step_deg:=0.25` 控制密集路点；`cartesian_deg_per_sec:=8.0` 是当前已固化拧紧速度。
- `fk_xy_tolerance_m:=0.0025`、`fk_z_tolerance_m:=0.0015` 和 `joint_jump_deg:=8.0` 是安全检查，不要为了拧松盲目放宽。
- `l7_seed_min/max` 约 `-38/+38°`；日志出现 `seed_l7=38°` 时，应理解为构型空间不足，而不是简单提高上限。

**重夹循环：**

```text
闭合 → 旋转 → 松爪 → 固定 TCP 回正 → 再闭合
```

- `reclose=true` 与 `release_pos=35` 用于棘轮式多轮动作。
- 建议测试顺序为 `1轮 → 3轮 → 10轮 → 完整轮数`。
- 总角度按 `cycles × abs(cycle_deg)` 计算；例如 `5×15°=75°`，`12×15°=180°`。
- 一轮只完成部分路点时，程序应回正并报告实际完成角度；不能把重复的小动作误计入累计拧盖进度。

### 16.10 推荐调参工作流

1. 先用 `cycles:=0` 只验证右手抓瓶、左手路径、触顶和初始夹爪落点。
2. 初始位置按 X、Y、Z 顺序调，每次只改一个参数，步长 `2～5mm`。
3. 确认瓶盖接触后，单独调静态姿态：先 wrist6，再 wrist5，再 pitch；不要叠加调参。
4. 拧紧和拧松分开标定；拧紧一旦稳定，任何拧松修正都必须使用 `loosen_*` 参数。
5. 拧松先一轮 `+5°` 或 `+15°`，观察初始高度、左右漂移、上下漂移和是否打滑。
6. 初始高度用 `left_cap_loosen_tcp_extra_z_m`；旋转左右用 `left_cap_loosen_y_comp_per_deg_m`；旋转上下用 `left_cap_loosen_z_comp_per_deg_m`；初始姿态用 `left_cap_loosen_pitch_extra_rad`。
7. 不要用 pivot、静态 TCP 或 pitch 去掩盖旋转中的漂移，也不要用动态补偿去修正初始位置。
8. 确认单轮完整后，再打开 `reclose` 测试3轮，最后才扩大轮数。
9. 每次实机测试记录动作模式、所有覆盖参数、视觉/抓取坐标、触顶 Z、旋转中心、补偿和实际完成角度。

### 16.12 当前日志判读模板

看到以下日志时按此解释：

```text
右手 TCP 打击点: X=... Y=... Z=...
```

检查右手三项 `right_tcp_extra_*` 和 `right_grasp_z_offset_m`。

```text
使用 HSV 瓶盖坐标 ... + extra=(x,y,z) → IK=(x,y,z)
```

这是左手初始落点，不是旋转中的动态目标。

```text
旋转中心: 使用=(...) 配置=(...) ... 配置中心误差=(...)
```

检查实际触顶中心、pivot、skip_align 和指尖/EE差异；不要只看配置中心。

```text
XYZ补偿=(x,y,z)mm/deg
```

这是每度动态位置命令。乘以本轮实际角度即可估算末端被程序主动移动的距离。

```text
seed_l7=38.0° IK无解
```

优先判断正向旋转构型余量是否耗尽；不要直接放宽 joint limit。

```text
仅规划成功 n/m 路点
```

实际只执行已校验路点，随后按程序回正；该轮不能按目标角度计入。
